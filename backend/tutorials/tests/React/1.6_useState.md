## What `useState` Solves

So far, our components are **static snapshots**. They render once based on props and never change. But UIs need to react to clicks, typing, toggles, timers. Components need **memory that persists between renders** and **triggers re-renders when changed**.

## The Mental Model: React Re-runs Your Function

React's core mechanism: **When state changes, React re-runs your component function with the new value.**

Think of each render as a photograph. State change? React takes a new photo and swaps it in — efficiently, only where differences exist.

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </div>
  );
}
```

## Breaking Down `useState`

```jsx
const [count, setCount] = useState(0);
```

| Part | Meaning |
|------|---------|
| `useState` | React function that creates a "state cell" tied to this component instance |
| `0` | **Initial value** — used only on first render |
| `count` | **Current value** — reads the state cell |
| `setCount` | **Setter function** — the *only* way to change this state |
| `[count, setCount]` | Array destructuring — React returns `[value, setter]` |

## The Rules of `useState`

**1. Never call conditionally**
```jsx
// WRONG — hooks must run in same order every render
if (condition) {
  const [state, setState] = useState(0);
}
```

**2. State updates are asynchronous**
```jsx
setCount(count + 1);
setCount(count + 1);  // Both use the SAME old value!
// Result: count increases by 1, not 2
```

To update based on previous state:
```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);  // Now increases by 2
```

**3. State is isolated per instance**
Each `<Counter />` has its own `count`. They don't share.

**4. State replaces, not merges**
For objects, spread the old state:
```jsx
const [user, setUser] = useState({ name: 'Alice', age: 30 });

// WRONG — loses age!
setUser({ name: 'Bob' });

// RIGHT — preserves age, updates name
setUser(prev => ({ ...prev, name: 'Bob' }));
```

## Why `setCount` Instead of `count = 5`?

Direct assignment doesn't work because:
- It doesn't tell React to re-render
- React has no way to know you changed something

`setCount` does two things:
1. Updates the state cell in React's internal memory
2. Schedules a re-render of that component

## Real-World Context

**When to use state:** Any data that changes over time and affects the UI.
- Form inputs
- Toggle switches (open/closed menus)
- Carts (items added/removed)
- Current page in pagination
- Loading indicators

**When NOT to use state:** Data that can be derived from existing state or props.
- Don't store `fullName` in state if you have `firstName` and `lastName` — compute it during render
