

## Topic 7: `useEffect` — Side Effects and Lifecycle

## What `useEffect` Solves

So far, our components are **pure functions of state and props**. They take inputs, return JSX. But real UIs need to interact with the outside world:
- Fetch data from an API
- Subscribe to a WebSocket
- Set up a timer
- Read from or write to `localStorage`
- Update the document title

These are **side effects** — things that happen outside React's render cycle. `useEffect` is the hook for managing them.

## The Mental Model: Synchronization

`useEffect` says: **"Run this code after React paints the screen, and keep it synchronized with these dependencies."**

```jsx
import { useState, useEffect } from 'react';

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const interval = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);

    return () => clearInterval(interval);
  }, []);

  return <p>{seconds} seconds elapsed</p>;
}

OR

import { useEffect, useState } from "react"

function App(){

    const [seconds, setSeconds ] = useState(0);
    function timer(){
        const interval = setInterval(() => (
            setSeconds(prev => prev + 1)
        ), 1000);
        return () => clearInterval(interval);
    }
    useEffect(timer, []);

    return (
        <p>Timer: {seconds}</p>
    )
}

export default App;
```

## Breaking Down `useEffect`

```jsx
useEffect(() => {
  // Setup code runs after render
  
  return () => {
    // Cleanup code runs before next effect or unmount
  };
}, [dependencies]);
```

| Part | What It Means |
|------|-------------|
| `() => {...}` | The **effect function** — runs after React paints the DOM |
| `return () => {...}` | The **cleanup function** — runs before the effect re-runs or component unmounts |
| `[dependencies]` | The **dependency array** — effect only re-runs if these values change |

## The Dependency Array Rules

**1. Empty array `[]` — run once on mount, cleanup on unmount**
```jsx
useEffect(() => {
  console.log("Component mounted");
  return () => console.log("Component unmounted");
}, []);
```

**2. With dependencies `[count]` — run when dependencies change**
```jsx
useEffect(() => {
  console.log(`Count changed to ${count}`);
}, [count]);
```

**3. No array — run after every render**
```jsx
useEffect(() => {
  console.log("Every render");
});
```

**4. Missing dependency — stale closure bug**
```jsx
useEffect(() => {
  console.log(count);  // If count isn't in deps, this logs stale value
}, []);  // ❌ Missing count
```

## The Cleanup Function

Effects that set up subscriptions, timers, or event listeners must clean up to prevent memory leaks:

```jsx
useEffect(() => {
  const handleResize = () => setWidth(window.innerWidth);
  window.addEventListener('resize', handleResize);
  
  return () => window.removeEventListener('resize', handleResize);
}, []);
```

**Rule:** If your effect creates something persistent (listener, timer, subscription), return a function that destroys it.

## Real-World Context

**When to use `useEffect`:**
- Data fetching (`fetch`, `axios`)
- Manual DOM manipulation (rarely needed in React)
- Subscriptions (WebSocket, browser events)
- Timers and intervals
- Syncing state to `localStorage`

**When NOT to use `useEffect`:**
- Transforming data for display (compute during render)
- Handling user events (use event handlers directly)
- Propagating state changes (use derived state)
