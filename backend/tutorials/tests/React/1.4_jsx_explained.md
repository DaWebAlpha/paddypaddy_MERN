## What JSX Actually Is

JSX looks like HTML, but it's **JavaScript**. When you write:

```jsx
const element = <h1>Hello, world</h1>;
```

This is **not** HTML in your JavaScript file. It's JSX, and it compiles to this:

```javascript
const element = React.createElement('h1', null, 'Hello, world');
```

Which then becomes a JavaScript object describing what to render. React reads that object and creates actual DOM elements.

## The Mental Model: JSX as a Value


This is the key insight: **JSX expressions are values**, just like numbers or strings. You can:

- Store them in variables
- Return them from functions
- Pass them as arguments
- Put them in arrays

```jsx
function App() {
  const greeting = <h1>Good morning</h1>;  // JSX is a value!
  const farewell = <h1>Good night</h1>;
  
  return (
    <div>
      {greeting}
      {farewell}
    </div>
  );
}
```

The curly braces `{}` are the escape hatch from JSX back into JavaScript. Anything inside `{}` is evaluated as JavaScript and its result is inserted into the output.

## Rules of JSX

**1. One Root Element**
JSX must return a single parent. This is invalid:

```jsx
// WRONG — two root elements
return (
  <h1>Title</h1>
  <p>Description</p>
);
```

This is valid:

```jsx
// RIGHT — wrapped in a parent
return (
  <div>
    <h1>Title</h1>
    <p>Description</p>
  </div>
);
```

Or use a **fragment** (a ghost wrapper that leaves no trace in the DOM):

```jsx
// RIGHT — fragment, no extra DOM node
return (
  <>
    <h1>Title</h1>
    <p>Description</p>
  </>
);
```

**2. All Tags Must Close**
HTML lets you get sloppy. JSX doesn't.

```jsx
// WRONG
<img src="photo.jpg">
<br>

// RIGHT
<img src="photo.jpg" />
<br />
```

**3. `className` instead of `class`**
`class` is a reserved JavaScript keyword. JSX uses `className`.

```jsx
// WRONG
<div class="container">

// RIGHT
<div className="container">
```

**4. `camelCase` for attributes**
HTML uses lowercase. JSX uses camelCase for multi-word attributes.

```jsx
// WRONG
<button onclick="handleClick()">
  <label for="name">

// RIGHT
<button onClick={handleClick}>
  <label htmlFor="name">
```

## JavaScript Inside JSX: The `{}` Escape Hatch

Curly braces let you inject any JavaScript expression into your JSX.

```jsx
function Greeting() {
  const name = 'Maria';
  const hour = new Date().getHours();
  const timeOfDay = hour < 12 ? 'morning' : 'afternoon';
  
  return (
    <div>
      <h1>Good {timeOfDay}, {name}!</h1>
      <p>You have {2 + 3} unread messages.</p>
    </div>
  );
}
```

This renders: *"Good afternoon, Maria!"* and *"You have 5 unread messages."*

**What you CAN put in `{}`:**
- Variables: `{name}`
- Expressions: `{2 + 3}`, `{isLoggedIn ? 'Yes' : 'No'}`
- Function calls: `{formatDate(createdAt)}`
- Other JSX: `{isAdmin && <AdminPanel />}`

**What you CANNOT put in `{}`:**
- `if` statements (use ternary: `condition ? x : y`)
- `for` loops (use `.map()` — we'll cover this in a later topic)
- Variable declarations (`const x = 5`)

## Conditional Rendering

Since `if` doesn't work inside `{}`, you use these patterns:

**Ternary for either/or:**
```jsx
function StatusMessage({ isOnline }) {
  return (
    <p>
      {isOnline ? 'User is online' : 'User is offline'}
    </p>
  );
}
```

**Logical AND for show/hide:**
```jsx
function Notification({ count }) {
  return (
    <div>
      <h1>Dashboard</h1>
      {count > 0 && <p>You have {count} alerts</p>}
    </div>
  );
}
```

If `count` is 0, the whole expression evaluates to `false` and React renders nothing. If `count` is 5, it renders the `<p>`.

**Why this works:** In JavaScript, `true && <p>...</p>` evaluates to `<p>...</p>`. `false && <p>...</p>` evaluates to `false`. React ignores `false`, `null`, and `undefined` in JSX — it simply renders nothing.

## Real-World Context

**When to use fragments:** Any time you need to return multiple elements without adding a meaningless wrapper `<div>` to the DOM. Common in table rows, lists, or when the parent CSS expects direct children.

**When to use ternary vs. AND:** Ternary when you need *either A or B*. AND when you need *A or nothing*.
