## Topic 3: Props — Passing Data Into Components

## The Mental Model: Functions with Arguments

A component is a function. Functions take arguments. Props are how you pass arguments to components.

```jsx
// A regular function
function greet(name, role) {
  return `Hello, ${name}. You are a ${role}.`;
}

greet("Alice", "Admin");

// A React component (same idea, different syntax)
function UserCard(props) {
  return <p>Hello, {props.name}. You are a {props.role}.</p>;
}

<UserCard name="Alice" role="Admin" />
```

When you write `<UserCard name="Alice" />`, React bundles all those attributes into a single object called `props` and passes it as the first argument to your function.

```jsx
// What React actually does behind the scenes:
UserCard({ name: "Alice", role: "Admin" });
```

## Accessing Props: Two Styles

**Style 1: `props` object directly**
```jsx
function UserCard(props) {
  return (
    <div>
      <p>{props.name}</p>
      <p>{props.role}</p>
    </div>
  );
}
```

**Style 2: Destructuring in the parameter (what you used)**
```jsx
function UserCard({ name, role }) {
  return (
    <div>
      <p>{name}</p>
      <p>{role}</p>
    </div>
  );
}
```

Both are identical. Destructuring is just JavaScript syntax sugar. Use whichever you prefer — most React developers use destructuring because it's cleaner.

## Props Are Read-Only

**You cannot modify props inside a component.** This is a hard rule in React.

```jsx
function UserCard({ name }) {
  name = "Bob";  // ❌ WRONG — never do this
  return <p>{name}</p>;
}
```

Props flow **one direction**: parent down to child. If a child needs to change data, the parent must change it and pass new props. This is called **unidirectional data flow**, and it's the foundation of React's predictability.

## Default Values

When a parent doesn't pass a prop, you can provide a fallback:

```jsx
function UserCard({ role = "User" }) {
  return <p>Role: {role}</p>;
}

<UserCard />              // Renders: "Role: User"
<UserCard role="Admin" /> // Renders: "Role: Admin"
```

## The Spread Operator with Props

Sometimes you have an object and want to pass all its properties as individual props:

```jsx
const user = { name: "Alice", role: "Admin", age: 33 };

<UserCard {...user} />
// Equivalent to:
<UserCard name="Alice" role="Admin" age={33} />
```

## Real-World Context

**When to use props:** Every time a component needs to show different data or behave differently depending on where it's used. A `Button` component that always says "Click me" is useless. A `Button` that accepts `label`, `color`, and `onClick` props can be used 50 different ways.

**Why read-only matters:** If any component could change props, you'd have no idea where data changed. Debugging would be a nightmare. By making props immutable, React guarantees that a component's output is 100% determined by its inputs.
