**Short answer:** For this assignment, yes. Because we haven't learned arrays yet.

**Long answer:** In real React, you'd store tasks in **one array** with `useState`, not five separate booleans:

```jsx
const [tasks, setTasks] = useState([
  { id: 1, title: "Fix login bug", priority: "High", isCompleted: false },
  { id: 2, title: "Write tests", priority: "Medium", isCompleted: false },
  // ... etc
]);
```

Then you'd use `.map()` to render them. But we haven't covered:
- Arrays in state
- Object spreading (`...task`)
- `.map()` for rendering lists
- Unique `key` props

That's **Topic 6**.

The five separate `useState` declarations are verbose but explicit. They teach you that **each piece of state is independent** and **each state setter triggers its own re-render**. When you move to arrays, you'll appreciate the abstraction.

## Topic 6: Arrays, Objects, and `.map()` — Rendering Lists

## The Mental Model: From Static to Dynamic

So far, we've manually written each component instance:
```jsx
<TaskCard ... />
<TaskCard ... />
<TaskCard ... />
```

This doesn't scale. Real UIs have dynamic data — from APIs, databases, user input. You don't know how many items you'll have. You need a **pattern for rendering any number of items from an array**.

---

## The `.map()` Pattern

`.map()` transforms an array into JSX:

```jsx
const tasks = [
  { id: 1, title: "Fix bug", priority: "High" },
  { id: 2, title: "Write tests", priority: "Medium" }
];

function TaskList() {
  return (
    <div>
      {tasks.map(task => (
        <TaskCard 
          key={task.id}
          title={task.title} 
          priority={task.priority} 
        />
      ))}
    </div>
  );
}
```

**What `.map()` does:**
- Takes each item in the array
- Runs your function with that item
- Returns a new array of whatever your function returns (in this case, JSX elements)
- React renders that array of elements

## The `key` Prop — Why It's Required

React needs `key` to track which item is which across re-renders. Without it, React can't efficiently update, reorder, or remove items.

**Rules for `key`:**
- Must be **unique** among siblings
- Must be **stable** across renders (don't use array index if order changes)
- Must be **predictable** (don't use `Math.random()`)

**Good keys:** Database IDs, UUIDs, timestamps from creation
**Bad keys:** Array indices (if order changes), random numbers

## Object State Updates

When state is an array of objects, you can't mutate it directly. You must create a new array with the updated item:

```jsx
function toggleTask(id) {
  setTasks(prev => prev.map(task => 
    task.id === id 
      ? { ...task, isCompleted: !task.isCompleted } 
      : task
  ));
}
```

**What `...task` does:** Spreads all existing properties of the task object, then overrides `isCompleted` with the new value. This creates a new object, leaving the old one unchanged.
